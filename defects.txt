Defect Report for Flask Log Management System

Summary:
- Verifying README.md examples and code behavior against app implementation.

Defect list (classified by sub-type):

1) Incorrect docs
- Allowed `level` values mismatch
  - README.md lists: DEBUG, INFO, WARN, ERROR
  - Code uses: DEBUG, INFO, WARNING, ERROR (ALLOWED_LEVELS set)
  - Impact: Using 'WARN' returns 400 (invalid level).
  - Example reproduction:
    - POST /logs with {"level": "WARN", "message": "x"} -> 400

- `context` type enforcement mismatch
  - README states: `context` must be a JSON object
  - Code accepts any JSON-serializable value (object, array, string, number) and stores it as text.
  - Impact: Examples that only show objects are fine; however, behavior is more permissive than docs.

2) Outdated docs
- Notes section "Allowed levels" uses `WARN` instead of `WARNING`.
- No mention of case sensitivity: code requires exact uppercase values.

3) Missing docs / Onboarding
- Activation of PowerShell virtualenv may require temporary ExecutionPolicy adjustment on Windows (Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force).
- No guidance about installing developer/test dependencies like pytest and requests.
- Not stated that `level` is required (create endpoint returns 400 if omitted).
- Not documented behavior of response codes (201 for create; 400 for invalid; 204 for delete; 200 for list/export).
- No mention of `--init-db` and that it creates `data.db` in application dir (it is in Quick Start but should be emphasized).

4) Tutorials (examples that don't run as described)
- PowerShell `ConvertTo-Json` depth: The default may truncate nested objects; use `ConvertTo-Json -Depth 10` to preserve nested objects in JSON bodies.
- Windows PowerShell commands should ensure `.venv` activation and execution policy; otherwise Activate.ps1 may be blocked.

5) Implementation & operational issues (observed while running tests)
- PermissionError when removing `data.db` on Windows during tests due to open SQLite connections (file lock).
  - Trace (from failed pytest run before test isolation fix):
    E           PermissionError: [WinError 32] The process cannot access the file because it is being used by another process: '.../data.db'
    - Cause: app code opens sqlite3 connections but does not explicitly close them in many functions. Creating and closing connections with `conn.close()` or using context managers prevents locks.
  - Proposed fix: Use `with sqlite3.connect(DB_PATH) as conn:` or call `conn.close()` after operations.

6) Requirements and CI gaps
- README implies `pip install -r requirements.txt` but requirements.txt only included Flask; tests and example usage need `pytest` and `requests` (or the README should indicate installing them for development).

7) Behavior nuances
- Filtering by `level` uses SQL `LIKE` operator ("WHERE level LIKE ?"), allowing wildcard matching if desired; README doesn't document wildcard support, but it's accepted behavior.
- List logs returns context parsed to JSON where possible; if parsing fails it returns string; README doesn't explain how context is returned.

Notes: All endpoints otherwise behave as described (create, list, delete, export). DB file path is data.db in the application directory by default.

Recommended corrections are applied to `corrected_readme.md` and tests were added to `test_files/` to rationalize these behaviors.
