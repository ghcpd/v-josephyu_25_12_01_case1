DEFECT #1: Incorrect allowed level values
Location: README.md - "Notes" section
Documented: "Allowed levels: `DEBUG`, `INFO`, `WARN`, `ERROR`"
Actual: ALLOWED_LEVELS = {"DEBUG", "INFO", "WARNING", "ERROR"} (in app.py line 23)
Error: When using "WARN" as documented, API returns:
  HTTP 400 - {"error": "invalid level"}
Impact: Users following documentation will get errors when trying to use "WARN" level
Fix Required: Change documentation from "WARN" to "WARNING"

DEFECT #2: Database initialization command behavior not documented
Location: README.md - "Quick Start" section, step 2
Documented: "python app.py --init-db" appears to only initialize the database
Actual: The command initializes the database BUT ALSO starts the Flask server (app.py lines 117-120)
Error: Server runs after init instead of exiting, blocking the terminal
Impact: Users cannot proceed to step 3 as the server is already running and blocking
Fix Required: Document that --init-db also starts the server, or fix the code to exit after init

DEFECT #3: Level filter uses LIKE instead of exact match
Location: README.md - "API Examples" section
Documented: "Filter logs by `level`" (implies exact match)
Actual: Query uses "WHERE level LIKE ?" (app.py line 71) which does pattern matching
Error: Filtering may return unexpected results with partial matches
Impact: If documentation stated exact match filtering, the SQL LIKE may not behave as expected
Note: This is an implementation vs documentation inconsistency in behavior description
