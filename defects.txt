Defects Report for Flask Log Management System (Documentation-only issues)

1) Incorrect docs: Allowed levels mismatch
- README allowed levels: `DEBUG`, `INFO`, `WARN`, `ERROR`.
- Code ALLOWED_LEVELS: `{"DEBUG", "INFO", "WARNING", "ERROR"}`.
- Evidence: posting `{"level":"WARN"}` returns 400 invalid level.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   $body = @{ level = "WARN"; message = "m" } | ConvertTo-Json
   Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" -ContentType "application/json" -Body $body
   ```
   Linux/macOS (bash):
   ```bash
   curl -X POST http://127.0.0.1:5000/logs \
     -H "Content-Type: application/json" \
     -d '{"level":"WARN","message":"m"}'
   ```


2) Onboarding: Expectations vs. actual behavior not documented
- Docs do not warn about potential SQLite lock scenarios (connections not closed in code by design for testing).
- Evidence: intermittent `sqlite3.OperationalError: database is locked` when POST and /export happen concurrently.
 - Reproduction:
   Windows PowerShell (run export while posting logs):
   ```powershell
   $body = @{ level = "INFO"; message = "lock-test" } | ConvertTo-Json
   1..20 | ForEach-Object { Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" -ContentType "application/json" -Body $body } | Out-Null
   Invoke-WebRequest -OutFile logs.csv -Uri "http://127.0.0.1:5000/export"
   ```
   Linux/macOS (bash):
   ```bash
   for i in $(seq 1 20); do curl -s -X POST http://127.0.0.1:5000/logs -H 'Content-Type: application/json' -d '{"level":"INFO","message":"lock-test"}' & done; wait
   curl -o logs.csv "http://127.0.0.1:5000/export"
   ```

3) Incorrect docs: `context` must be JSON object vs actual behavior
- README states `context` must be a JSON object.
- Code accepts any JSON value and blindly `json.dumps(context)` including strings/arrays.
- Evidence: POST with `context: "x"` succeeds.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   $body = @{ level = "INFO"; message = "ctx"; context = "x" } | ConvertTo-Json
   Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" -ContentType "application/json" -Body $body
   ```
   Linux/macOS (bash):
   ```bash
   curl -X POST http://127.0.0.1:5000/logs \
     -H "Content-Type: application/json" \
     -d '{"level":"INFO","message":"ctx","context":"x"}'
   ```

4) Outdated docs: Exact match level vs LIKE query
- README implies precise filter `level=INFO`.
- Code uses `WHERE level LIKE ?` which can match prefixes or patterns if user passes `%`.
- Evidence: `level=%` returns all rows.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   Invoke-RestMethod -Uri "http://127.0.0.1:5000/logs?level=%&page=1&per_page=5"
   ```
   Linux/macOS (bash):
   ```bash
   curl "http://127.0.0.1:5000/logs?level=%&page=1&per_page=5"
   ```

5) Missing docs: CSV export will overwrite `logs.csv` in app directory
- Not documented that export rewrites a fixed path; no option to change path.
- Evidence: multiple exports replace previous file.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   Invoke-WebRequest -OutFile logs.csv -Uri "http://127.0.0.1:5000/export"
   Invoke-WebRequest -OutFile logs.csv -Uri "http://127.0.0.1:5000/export"
   ```
   Linux/macOS (bash):
   ```bash
   curl -o logs.csv "http://127.0.0.1:5000/export"
   curl -o logs.csv "http://127.0.0.1:5000/export"
   ```

6) Tutorials: `--init-db` followed by immediate concurrent operations may lock
- Command runs but connection is left open; while server starts, subsequent writes may hit locks.
- Evidence: after init and quick POST: occasional lock.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   python app.py --init-db
   $body = @{ level = "INFO"; message = "post-after-init" } | ConvertTo-Json
   Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" -ContentType "application/json" -Body $body
   Invoke-WebRequest -OutFile logs.csv -Uri "http://127.0.0.1:5000/export"
   ```
   Linux/macOS (bash):
   ```bash
   python3 app.py --init-db
   curl -X POST http://127.0.0.1:5000/logs -H 'Content-Type: application/json' -d '{"level":"INFO","message":"post-after-init"}'
   curl -o logs.csv "http://127.0.0.1:5000/export"
   ```

7) Outdated docs: Pagination defaults correct but total counts missing
- README claims pagination defaults but not documented that response omits `total` count.
- Expected behavior often includes total; docs mismatch typical behavior.
 - Reproduction:
   Windows PowerShell:
   ```powershell
   $resp = Invoke-RestMethod -Uri "http://127.0.0.1:5000/logs?page=1&per_page=2"
   $resp | ConvertTo-Json -Depth 5
   # Observe keys: items, page, per_page (no total)
   ```
   Linux/macOS (bash):
   ```bash
   curl "http://127.0.0.1:5000/logs?page=1&per_page=2"
   # Observe JSON lacks total
   ```
