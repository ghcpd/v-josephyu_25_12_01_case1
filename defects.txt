### [OUTDATED_DOCS] - Deprecated datetime.utcnow()
**Type:** Outdated docs - behaviors changed in code but docs still reflect old behavior
**Severity:** MEDIUM (Python 3.13 warning)
**Location:** app.py, line 49
**Issue:** Using `datetime.utcnow()` which is deprecated in Python 3.12+ and scheduled for removal
**Error Trace:**
```
DeprecationWarning: datetime.datetime.utcnow() is deprecated and scheduled 
for removal in a future version. Use timezone-aware objects to represent 
datetimes in UTC: datetime.datetime.now(datetime.UTC).
```
**Current Code:**
```python
created_at = datetime.utcnow().isoformat()
```
**Recommended Fix:**
```python
from datetime import datetime, timezone
created_at = datetime.now(timezone.utc).isoformat()
```
**Impact:** Code will break in future Python versions, generates warnings in Python 3.13
**Fix Required:** Update to use `datetime.now(timezone.utc)`

**Severity:** MEDIUM
**Location:** README.md, lines 59-62
**Issue:** PowerShell example for creating log with context has incorrect JSON syntax
**Documented Example:**
```powershell
$body = @{ level = "INFO"; message = "Started"; context = @{ user = "alice" } } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" -ContentType "application/json" -Body $body
```
**Test Result:** Command works but converts nested hashtable to JSON with extra structure
**Problem:** The context object becomes nested, which may not match user expectations
**Better Example:**
```powershell
$body = @{
    level = "INFO"
    message = "Started"
    context = @{ user = "alice" }
} | ConvertTo-Json -Depth 10
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:5000/logs" `
    -ContentType "application/json" -Body $body
```
**Impact:** Users may get unexpected JSON structure in their context field
**Fix Required:** Update PowerShell examples with proper JSON formatting

### [ONBOARDING] - .init-db Command Exit Behavior Unclear
**Type:** Onboarding - unclear setup steps
**Severity:** MEDIUM
**Location:** README.md, lines 44-48 and app.py
**Issue:** The `--init-db` flag doesn't cleanly exit after initializing database
**Current Behavior:** Command initializes database but then starts the Flask development server
```python
if __name__ == '__main__':
    parser = argparse.ArgumentParser()
    parser.add_argument('--init-db', action='store_true')
    args = parser.parse_args()
    if args.init_db:
        init_db()
    app.run(host='0.0.0.0', port=5000, debug=True)  # <-- Always runs!
```
**Error:** After database initialization, the server starts (not documented)
**Impact:** Users expect `--init-db` to just initialize and exit, not start the server
**Expected Flow:**
```
User runs: python app.py --init-db
Expected: "Database initialized" → exits
Actual: "Database initialized" → server starts on port 5000
```
**Fix Required:** Exit after database initialization, don't start server
**Recommended Code:**
```python
if __name__ == '__main__':
    parser = argparse.ArgumentParser()
    parser.add_argument('--init-db', action='store_true')
    args = parser.parse_args()
    if args.init_db:
        init_db()
        print("Database initialized successfully at:", DB_PATH)
        exit(0)
    app.run(host='0.0.0.0', port=5000, debug=True)
```
