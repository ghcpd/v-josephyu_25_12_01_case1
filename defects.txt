Defect Report - Flask Log Management System

1) Incorrect docs: Allowed levels mismatch
- Sub-type: Incorrect docs
- Description: README.md listed allowed levels as `DEBUG`, `INFO`, `WARN`, `ERROR`. The implementation uses `WARNING` instead of `WARN` in `ALLOWED_LEVELS`.
- Reproduction:
  POST /logs with payload {"level":"WARN", "message":"x"}
  curl -X POST http://127.0.0.1:5000/logs -H "Content-Type: application/json" -d '{"level":"WARN","message":"x"}'
- Actual: HTTP 400 (invalid level)
- Expected: If docs were correct, this call should return 201. Alternatively, docs should be updated to `WARNING`.
- Recommendation: Update README allowed values to `WARNING` or accept `WARN` as alias in code.

2) Incorrect docs / Implementation: `context` validation mismatch
2) Incorrect docs / Implementation: `context` validation mismatch
- Sub-type: Incorrect docs (and implementation bug)
- Description: README states `context` must be a JSON object; implementation previously accepted other JSON types and did not validate the structure.
- Reproduction (automated test): test_create_log_context_string in tests
  Payload: {"level": "INFO", "message": "String context", "context": "not-an-object"}
  Previously, POST returned 201 (Created) — violation of stated requirement.
  After applying a fix, `create_log()` now validates that `context` is a JSON object and returns 400 when invalid.
  Proof: Unit tests in `test_files/test_app.py` assert the correct behavior; all tests pass now.
- Recommendation: Keep validation implemented in `create_log()`. Update other endpoints or docs if additional `context` usages exist.

- Recommendation: Either add docs to specify allowed context types (any JSON value), or modify code to enforce object-only behavior.

4) Potential compatibility issue: `send_file` `download_name` param
- Sub-type: Outdated docs / Tutorials
- Description: Flask's `send_file` has used `download_name` parameter in recent versions (Flask 2.2+). In older Flask versions `attachment_filename` was used. README assumes typical curl/Invoke-WebRequest usage, not parameter name.
- Reproduction: If using an older Flask version, `send_file(..., download_name=...)` might raise TypeError.
- Recommendation: Keep Flask pinned to 3.0.0 in `requirements.txt` or update the docs to mention that `Flask>=2.2` should be installed.

5) Minor: `page` and `per_page` validation not documented
- Sub-type: Missing docs
- Description: The code casts `page` and `per_page` to ints without validating >0. The README states defaults but doesn't warn about invalid numeric values.
- Recommendation: Add doc mention and add validation to code for positive integers.
