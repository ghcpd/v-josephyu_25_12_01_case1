Documentation & Knowledge Defects
=================================

Sub-Type: Incorrect docs
------------------------
1) Allowed levels mismatch
   - Doc (README.md) states allowed levels: `DEBUG`, `INFO`, `WARN`, `ERROR`.
   - Implementation (`app.py`): `ALLOWED_LEVELS = {"DEBUG", "INFO", "WARNING", "ERROR"}` – `WARN` is **not** accepted.
   - Evidence: `test_create_log_rejects_invalid_level` asserts POST with `{"level":"WARN"}` returns 400 `invalid level`.

2) `context` validation overstated
   - Doc claims `context` *must* be a JSON object.
   - Implementation accepts any JSON value; it is serialized with `json.dumps` without type checking.
   - Evidence: `test_context_non_object_is_accepted` posts `context` as a string and receives 201 Created.

Sub-Type: Missing docs
----------------------
1) Delete semantics
   - Doc says “Delete logs by ID” but does not clarify response behavior.
   - Implementation always returns `204 No Content` even when the ID doesn’t exist (idempotent delete).
   - Consider documenting this for clients expecting 404.

Sub-Type: Onboarding / Tutorials
--------------------------------
1) Test tooling omitted
   - Original `requirements.txt` lacked `pytest`, so `README` users cannot run tests as-is.
   - We added `pytest` to `requirements.txt` and provided `run_tests.ps1` / `run_tests.sh`.

2) Test instructions absent
   - Original `README.md` did not describe how to run tests.
   - `corrected_readme.md` now includes test execution guidance.

Notes (Code-level warning)
--------------------------
- `datetime.utcnow()` is deprecated in Python 3.13; consider `datetime.now(datetime.UTC)`.
