# Detected Defects in Documentation vs Implementation

## Incorrect Docs

- Allowed log levels mismatch
  - Location: `README.md` under Notes
  - Expected per docs: `DEBUG`, `INFO`, `WARN`, `ERROR`
  - Actual in code: `DEBUG`, `INFO`, `WARNING`, `ERROR` (see `app.py` ALLOWED_LEVELS)
  - Evidence: POST request with `level: WARN` returns 400.
    - Example trace (from running app test client):
      `invalid level status 400 {'error': 'invalid level'}`
  - Classification: Incorrect docs

- `context` type requirement
  - Location: `README.md` states: "`context` must be a JSON object"
  - Actual behavior: the application accepts any JSON value (object, string, number, array) and stores it as text; it doesn't validate that `context` is strictly an object.
  - Evidence: POST with `context` as string returns 201 successfully.
  - Classification: Incorrect docs

## Outdated Docs

- None significant found beyond the `WARN` vs `WARNING` mismatch which indicates doc drift; README lacked mention of parsed `context` returned in responses.

## Missing Docs

- CSV export header and filename
  - Location: `README.md` Export CSV section does not state that the response will be a CSV with header: `id, level, message, context, created_at`
  - The `server` returns a `Content-Disposition` header to indicate filename `logs.csv`; docs do not explicitly mention the default filename.
  - Classification: Missing docs

- What `context` is returned as in response
  - Location: `README.md` does not specify the returned representation for `context` (app returns parsed JSON back as object or value).
  - Classification: Missing docs

## Tutorials

- The Windows PowerShell examples will work but could fail if PowerShell's `ConvertTo-Json` produces unexpected quoting; recommend small note that `ConvertTo-Json` returns a string and to ensure valid JSON is posted.
  - Classification: Tutorials (clarification)

## Onboarding

- Requirements missing for running tests
  - `requirements.txt` lacked `pytest`; the environment cannot run tests without it.
  - Classification: Onboarding

## Error traces (from test run)

- PermissionError when cleaning up temp file due to file handle in use during export testing (non-critical)
  - Trace excerpt:
    `PermissionError: [WinError 32] The process cannot access the file because it is being used by another process: '...tmp0vzr7ihs'`
  - Classification: Runtime error during testing; not an app defect.
